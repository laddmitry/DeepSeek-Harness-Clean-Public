# Происхождение и проверка

Публикационная копия взята из сохранённого рабочего source. FILES.sha256.json фиксирует SHA256 всех файлов, кроме самого manifest. SOURCE_PROVENANCE.json содержит исходные хеши и совпадения копии; SOURCE_CHANGES.csv отделяет поздние отличия от supplied candidate. Рабочий source после подготовки проверяется по полному исходному manifest и не изменяется.

Связь с прежним runtime подтверждена выбранными installation config/compiled artefact hashes и журналами сборки. Полное побайтовое соответствие каждого исходника всем VM-built artefacts **NOT VERIFIED**: полный VM source/runtime linkage manifest в доступной host-копии отсутствует. Новый kit/docs и исключение gateway дополнительно отличают комплект от стенда. Не называйте будущий commit целиком прошедшим старые runtime tests.

Бинарные compiled файлы не включены.

Проверка нового локального commit описана в [GitHub Desktop](PUBLISH_GITHUB_DESKTOP_RU.md). `kit/Verify-Publication.py` сравнивает набор и SHA256 committed blobs с manifest, проверяет выбранный target tree; review исторических commits выполняется отдельно и сообщает действительный SHA. Используйте доверенную исходную копию verifier и внешне сохранённый SHA manifest; иначе совместная подмена manifest/скрипта не обнаруживается. Проверка истории не заменяет ручной просмотр author email и secret scan. После любого изменения файлов manifest/архив нужно пересоздать и перепроверить; просто старый PASS неприменим.

Проверена сама утилита commit verification на изолированном synthetic Git fixture: полное подготовленное дерево с ранним subset commit принимается, новый unprepared committed blob отклоняется. После FIL-003 target-tree comparison отделён от history review, чтобы законные предыдущие версии не сравнивались с новым manifest. Это тест упаковки, не новый Harness runtime test. PowerShell scripts прошли синтаксический разбор без исполнения. Encrypted Office fixture прочитан: только `<Types/>`, 8 bytes.
